# Inside orch examples and their execution scope

`manifest.json` registers every original teaching program and supporting fixture. `validation/examples/manifest.json` joins those programs with the exhaustive chapter/appendix/lab/post fence inventory. A recorded pass applies only to its explicit target and runtime mode.

Exact source listings are **fragments**, including listings that start in the middle of a function. Their immutable link identifies the package, surrounding imports, dependent declarations and setup. Compile the unchanged containing package in a disposable copy of the locked Go 1.25.0 module; do not paste a clipped method into an empty module. Historical listings retain their separate commit and are archival evidence. Neither fragment compilation nor byte equality proves that default startup calls that package.

Complete teaching Go programs import Orch internal packages and therefore run below the disposable module's root. Copy the registered original file into the owned overlay path shown by its command record; copy unchanged private-package files only where the specific guide describes that requirement. Hashes identify both the canonical additions and copied inputs. The application corpus under `evidence/orch` is never an execution directory.

Shell fences are procedures rather than invented terminal transcripts. The inventory checks their syntax and source definitions; any operation without a matching actual command record remains expected-only. Optional daemon, listener and database procedures require their guide's owned environment, explicit gates and cleanup. YAML parsing is syntax validation; separately named parser/CLI tests establish only the fields their assertions inspect. The illustrative error JSON in Chapter 7 is labeled with `example-only` and is not a captured response.

The fake-runtime, in-process handler, real process, real Docker and owned PostgreSQL modes remain distinct. A successful deterministic fixture cannot satisfy a daemon or cross-process persistence claim. Original proposals such as the HA ADR are registered as design-only and have no fictitious build target.
