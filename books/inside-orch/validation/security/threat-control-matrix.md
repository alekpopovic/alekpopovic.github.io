# Threat and control matrix

Six actor classes were kept separate: unauthenticated network actor, viewer, operator/workload author, namespace administrator, compromised agent and trusted host/debug administrator. The rows trace each accepted input or disclosure surface rather than extending one control to unrelated egress paths.

| ID | Actor and surface | Control and boundary |
| --- | --- | --- |
| SEC-01 | Unauthenticated network actor: Public API :8080 | Nonempty JWT enables protected-route bearer/RBAC checks; healthz/readyz/metrics remain exempt. Empty JWT disables user enforcement. Default bind/exposure and signing-secret configuration belong to operator; green probes do not authenticate writes. |
| SEC-02 | Viewer: Scoped service/task/log/secret metadata reads | requiredRole permits selected GETs; metadata omits plaintext; audit listing requires admin. Workload stdout can contain secrets; readable logs are not universally sanitized. |
| SEC-03 | Operator / authenticated workload author: Service create/update, scale and rollout | Ordinary mutations enter built-in admission/reference/quota paths; jobs/newer routes can use admin fallback. Do not infer all workload types share ServiceSpec admission or resource propagation. |
| SEC-04 | Namespace administrator: Explicit selected namespace and object IDs | RoleForNamespace and Matches establish logical context; namespace management additionally requires a valid global role. Namespace admin is an admin role scoped in JWT, not a new independent global role or network boundary. |
| SEC-05 | Compromised agent: Assigned task polling/reporting | Opaque32-byte-issued bearer token validated against node-bound hashed record, expiry/revocation and task ownership. Authorized execution includes decrypted secrets; daemon authority makes host compromise consequential. |
| SEC-06 | Enrollment authority holder: Bootstrap registration and re-enrollment | Bootstrap enrollment is separate from15-minute node bearer credentials; new issuance clears revoked record. Bootstrap custody remains important after revocation; no certificate/mTLS identity is active. |
| SEC-07 | Agent credential holder: Rotation | Server replaces credential record before response; lost rotation response can strand old bearer. Not a seamless recovery guarantee; retain response-loss scenario and separately design dual-token/ack protocol. |
| SEC-08 | Agent log consumer: Agent log listener :8081 | Startup bootstrap token protects log route; node-enrolled credential is a different protocol. Actual bind is configurable; endpoint is not automatically confined to loopback by its advertised URL. |
| SEC-09 | Debug administrator: Separate optional pprof listener | Disabled by default, configured loopback default; direct handler has no authentication. Changing debug address to public changes exposure; public API JWT does not wrap this separate listener. |
| SEC-10 | DNS client: Optional ORCH_DNS_ADDR UDP listener | Only started when configured; namespace name selects query records. No user JWT/RBAC on DNS; address spelling does not provide confidentiality or tenant network isolation. |
| SEC-11 | Probe configuration author: HTTP/TCP health egress | Validated path/scheme, assigned published port, agent-generated loopback target, timeout, same-origin redirects and64KiB read cap. Generic checker accepts arbitrary initial Target from another caller; no universal allowlist inferred. |
| SEC-12 | Notification sink author: HTTP webhook egress | URL validation, timeout, retry and optional HMAC signature; selected redaction. No inherited healthcheck destination restrictions; default redirect behavior separate; body drain is time-bounded rather than size-capped. |
| SEC-13 | GitOps source author: git clone outbound/filesystem path | Reject obvious URL credentials; argument slice and bounded owned checkout; configured path validation. No healthcheck egress allowlist; Git transport/configuration and path/symlink behavior need separate controls. |
| SEC-14 | Secret metadata reader / authorized task recipient: Envelope and Env delivery | AES-GCM nonce-prefixed ciphertext and KeyID authenticated data; decrypt only for relevant task execution. Plaintext necessarily exists in server/agent/daemon/application; key separate from database dump; no KMS rotation. |
| SEC-15 | Workload author and daemon administrator: SecurityContext→Engine | Ordinary service SecurityContext propagated to user/rootfs/capabilities/host options; static policy denies risky defaults. Writable mounts remain separate; Docker socket/host kernel common trust domain; resource limits dropped on ordinary path. |
| SEC-16 | Image supplier: ParserResolver and proposed trust adapters | Supplied digest syntax/pinning implemented; signatures/SBOM/scanning are design-only plus supplied-verdict teaching contract. No remote registry resolution, authenticity or vulnerability guarantee; fake-verdict pass is not scanner execution. |
| SEC-17 | Volume claimant: Physical volume naming | Namespace-local metadata resolves VolumeName into Docker bind name. No namespace/UUID suffix added to physical name; metadataRWO cannot fence stale writer or replicate bytes. |
| SEC-18 | Incident reader: Authored and captured artifacts | Static high-signal scan plus manual synthetic fixture/channel inspection. No key/token/private-author-email hits in scanned authored text; pattern scan alone is not a secrecy proof. |

The matrix is an audit of the edition’s security statements, not a certification of the application. Current controls, missing field propagation, unwired modules and design-only verifier/network/plugin proposals remain distinct. Controlled experiments used synthetic data and owned loopback targets; no live site or shared cluster was probed.
