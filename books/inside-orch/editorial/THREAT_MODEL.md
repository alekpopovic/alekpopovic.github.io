# Trust boundaries and source-scoped security

Edition `cbfc94ade5b57e449d6b73bf1485b1c5b1647022`, review 2026-10-13T00:35:06.866797+00:00. Findings below distinguish observed source behavior from hypotheses requiring experiments. This is an engineering threat model, not a claim of exploited vulnerabilities or production certification.

## Authority flow

Operator → HTTP API → namespace/RBAC/admission → in-memory domain state → assigned task → agent credential → Docker socket → container. The server also reaches Git sources, notification receivers and optionally DNS/database/debug consumers. The image registry sees pull/auth requests from Docker. The database store is a separate composition path, not automatic backing for API memory maps.

## Default and optional authentication

User JWT verification is conditional on a nonempty secret; otherwise protected user routes bypass it. HS256 verification checks expiry when `exp > 0`, so a missing expiry is not rejected by that check. Static user configuration can replace token namespace roles with a global role. Registration bootstrap authentication is optional when the configured token is empty; built-in server/agent defaults instead supply a documented development token. JWT secret defaults empty. These are development conditions, not evidence that node report authentication is optional: report, task retrieval and heartbeat require current per-node credentials. A new server loses their hashes with its maps.

Native listeners use HTTP. External TLS termination is deployment composition, not a source-provided mTLS agent identity. The server-to-agent log path uses bootstrap-token authority, distinct from the node credential accepted by server endpoints. Treat advertise addresses as outbound destination input and inspect log-stream dialing separately before declaring all SSRF surfaces bounded.

## Health validation versus network execution

The active agent's probe builder does not accept an arbitrary hostname: it constructs `127.0.0.1` plus an assigned published TCP port. The generic checker can be called with arbitrary targets; its HTTP client uses the default transport and same-origin redirect restriction. Thus hostname resolution/proxy behavior in the generic API and literal-loopback behavior in the active caller are different claims. Same-origin comparison prevents cross-origin redirects, but does not by itself pin DNS or prove every caller safe. No DNS-rebinding exploit was run for this record.

Notification sink validation permits URL destinations but does not establish an egress allowlist. A signature proves possession of a signing secret to a receiver; it does not authorize that receiver's address. Use injected transports or loopback fixtures to investigate redirect forwarding and redaction, never real internal/cloud endpoints. Git clone is launched as an argument vector with `--`, preventing shell interpolation through that argument. Git's protocols, environment and filesystem traversal remain separate issues.

## Filesystem and container isolation

GitOps rejects absolute and parent-escaping lexical paths. Its selected base uses `os.Stat`, then manifests use `os.ReadFile`; both can follow links. A YAML symlink is not a directory and may be collected by WalkDir. This is a **source-derived boundary concern**, not a demonstrated arbitrary-secret-read vulnerability. Test with a harmless file in a second temporary directory and record what is actually read; do not target credentials.

Namespace and RBAC checks restrict API views and mutations. They do not create separate kernels, network stacks, Docker daemons or cryptographic volumes. Admission defaults reject privilege/host namespaces/capabilities/host paths unless configured to allow them. Docker socket access still gives the trusted agent powerful host-level authority. Tenancy guarantees must state both API namespace scope and host runtime scope.

## Secret lifecycle and redaction

The local envelope uses AES-GCM with random nonces; source key material is locally configured or derived. There is no implemented KMS/key-rotation service to infer. API secret metadata avoids plaintext, but the assigned agent and Docker must receive values for execution. Docker administrators can inspect that boundary. Audit metadata redacts sensitive key substrings and URL user-info, while notification redaction has its own heuristic keys/text markers. Neither scrubs all strings or query values. Treat logs, events and errors as independently reviewable outputs using synthetic sentinel secrets.

## Testable release assertions

Unauthorized mutation leaves state unchanged. Wrong-node status reports cannot change another node's task. Rejected security specs do not reach CreateContainer. Public API secret metadata contains no synthetic plaintext. Audit and notification fixtures demonstrate their specific redactions and disclose remaining channels. GitOps local traversal tests use benign fixtures and report lexical-versus-symlink behavior. Debug surfaces stay on owned loopback listeners during inspection. Every runtime result needs its own timestamps, commands and sanitized logs; this model records static inspection only.
