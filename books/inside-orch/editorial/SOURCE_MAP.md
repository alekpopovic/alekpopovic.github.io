## The executable graph

`orch-server.main → loadConfig → run → NewMemoryService → controllers + API`. Startup receives flags/env/YAML configuration and a signal context. Optional `ORCH_SCHEMA_CHECK` opens PostgreSQL only for schema inspection; `migrate` is a separate main branch. Neither chooses a database-backed service. `orch-agent.main → loadConfig → NewEngineRuntimeFromEnv → WithMetrics → NewRunner.WithRuntime → Run`; its separate HTTP listener streams logs and metrics. `orch.main → cli.Execute → NewRootCommand → HTTP client → API`. `orch-loadtest` is a fourth executable, with its own memory service and synthetic state reporting, not the running network server.

## Interfaces and lifecycle

Consumer interfaces include agent.Client/Runtime/HealthChecker seams, scheduler.Store/Metrics, reconciler.Store/LeaderLock/Lease, rollout dependencies, events.Store, audit.Store, image.Resolver, secrets.Envelope, GitOpsFetcher, notification SinkStore and version compatibility helpers. The complete declaration index is in JSON and links every interface to a real line. `store.Store` embeds core namespace/quota/GitOps/node/service/task/deployment/event/secret/registry stores; the separately declared JobStore, CronJobStore, VolumeStore and NotificationSinkStore are **not** embedded. Do not infer PostgreSQL implementation of these additional interfaces. Lifecycle guards live in `pkg/types/lifecycle.go`, including actual and desired task transition validation, terminal-state checks and AgentCanReportTaskStatus. Current Go types use `internal/docker`; the intended application AGENTS layout includes `internal/runtime/docker` and `internal/runtime/containerd`, which are architecture aspirations rather than current paths.

## Experiments and test prerequisites

Pure/seamed tests: resource and image parsing, lifecycle transitions, scheduler.Plan, reconciler with fake store, fake Docker, admission/quota arithmetic, cron matching/injected clocks, local elector, and in-memory control-plane rules. HTTP httptest and loopback health tests still open local listeners. GitOps fixtures execute `git` in temporary repositories. Real Docker tests require `ORCH_DOCKER_INTEGRATION=1`; real orchestrator Docker E2E requires `ORCH_E2E_DOCKER=1`. PostgreSQL store tests require `ORCH_INTEGRATION_DATABASE_URL`; PostgreSQL E2E requires `ORCH_E2E_DATABASE_URL`. All database URLs must refer to disposable isolated databases: tests drop/reset public schema and are unsafe on an existing cluster. Optional 1,000-service test requires `-tags=scale`. Ordinary `go test ./...` can pass while these suites skip. Inventory inspected these conditions but ran no Go tests. Actual execution records belong under validation/labs.
