# Editorial plan: Inside orch

**Subtitle:** Building and Operating a Docker Orchestrator in Go
**Author:** Aleksandar Popovic
**Destination:** https://www.alekpopovic.com
**Language:** English
**Status:** Generation plan and complete authoring prompts; no completed manuscript is implied.

This should read as an engineering case study with one running lab, not a reordered documentation dump. Its distinction is traceable reasoning: intent in the original development prompt, real implementation changes, the current source, and the measured or expected operational behavior. The public narrative teaches the system; generation instructions remain in the companion pack.

Target 85,000–110,000 narrative words including appendices and answers. Aim for roughly 2,100 words per chapter, 1,300 per appendix, and concise front matter and solutions, then assess the actual manuscript. Rendered page count is a measured layout result.

## Progressive Atlas Lab

Atlas Lab begins with the actual upstream http-api deployment. It becomes a disposable small-platform case study with two logical namespaces, a finite report job, a local volume, and a GitOps configuration repository. Synthetic fixtures exercise distributed edge cases; real Docker/PostgreSQL variants prove only the runtime surfaces they execute. Teaching code stays outside evidence/orch.

## High-value contradiction checks

- `cmd/orch-server/main.go` constructs MemoryService. A configured DATABASE_URL or restored PostgreSQL backup does not make live state durable.
- Node monitoring is already wired in main even though architecture roadmap wording is stale. Use current code as authority.
- Scheduler package constraints and normal MemoryService placement must both be traced before asserting live resource/storage topology enforcement.
- Leadership and autoscaling packages exist but are not automatically active server integrations.
- Source resource declarations, admission/accounting, agent DTO propagation, and Docker enforcement are distinct links in the chain.
- DNS uses node addresses and host ports, not a workload overlay or service VIP.
- Signing, SBOM/scanning, external plugins, and advanced networking stay design-only unless a verified implementation changes that classification.
