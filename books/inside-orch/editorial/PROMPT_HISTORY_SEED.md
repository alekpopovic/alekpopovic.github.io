## Evidence method

Each mapping below was checked against `git diff-tree --no-commit-id --name-only -r <full-sha>`. Each selected anchor exists at that commit (`git cat-file -e <sha>:<path>`) and was actually changed there. The historical source links are pinned to the associated commit; the prompt links are pinned to the current snapshot. For code snippets, extract the exact historical version rather than silently substituting the latest file. See `evidence/prompt-commit-map.json` for machine-readable prompt hashes, associations, historical anchors and snapshot anchors.

The names of prompts and commits help select candidate associations, but the changed files are the supporting evidence. There is no execution transcript proving the precise prompt text was run at a historical commit. In particular prompts 00–28 were added retroactively on 14 July 2026, after their June implementation commits; prompt 26 maps to a targeted idempotency fix rather than a separately persisted full review report.

## Required honesty boundaries

1. **Live state is in memory.** `cmd/orch-server/main.go` calls `controlplane.NewMemoryService`. PostgreSQL implementation, migrations and test interfaces exist, but persistence is not wired into the default server. API services, events, audit history, namespace workloads and controller state must not be described as restart-safe durable orchestration. Source: [main](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/cmd/orch-server/main.go), [MemoryService](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/internal/controlplane/controlplane.go), [release boundary](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/RELEASE_NOTES.md).
2. **HA and autoscaling modules are not default-runtime capabilities.** The server main imports neither `internal/leadership` nor `internal/autoscaler`, and starts scheduler/rollout/node loops directly. Elector and CPU autoscaler packages have tests, but wiring is a future exercise. The autoscaler has a fake metrics provider and in-memory cooldown; the stabilization window field is reserved. Source: [autoscaler](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/internal/autoscaler/autoscaler.go), [autoscaling limits](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/AUTOSCALING.md), [leadership](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/internal/leadership/leadership.go).
3. **Digest parsing is not registry resolution.** Default `image.ParserResolver.Resolve` calls `Parse` and performs no network lookup. Accepting a supplied immutable digest and rejecting mutable tags is not equivalent to fetching and verifying a tag's digest from a registry. Source: [reference.go](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/internal/image/reference.go).
4. **Database backup is conditional on database-backed runtime state.** `docs/BACKUP_RESTORE.md` itself says durable persistence applies when the server is wired to PostgresStore. Backup scripts preserve neither MemoryService state nor Docker volume contents, local secret keys or TSDB/log state. Do not claim a database restore reconstructs the default running cluster. Source: [backup guide](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/BACKUP_RESTORE.md).
5. **Namespaces are logical isolation.** Cluster nodes, CPU capacity and host networking remain shared. Namespace-aware RBAC and ID hiding are not full hostile-tenant isolation. Source: [multi-tenancy boundaries](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/MULTI_TENANCY.md).
6. **Local volumes are not full stateful orchestration.** Local Docker volumes/claims/attachments exist, but replication, snapshots, stable ordered identities and distributed fencing remain design/out of scope. Source: [storage](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/STORAGE.md), [stateful design](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/STATEFUL_WORKLOADS_DESIGN.md).
7. **Fake load test is not production throughput.** The current loadtest evaluates in-process fake nodes/task transitions and scheduler/reconciler behavior. It does not measure PostgreSQL throughput, 1,000 real services, real image pulls, DNS/health latency or a durable multi-node cluster. Source: [scale caveat](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/docs/SCALE_TESTING.md), [loadtest command](https://github.com/alekpopovic/orch/blob/cbfc94ade5b57e449d6b73bf1485b1c5b1647022/cmd/orch-loadtest/main.go).
8. **Declared release gates are not observed runs.** CI source defines checks, but this audit has not observed GitHub Actions logs or executed tests. Code snippets and example commands must carry status such as source-extracted / tested / not-run / optional prerequisites. Do not claim gates passed solely from a prompt's acceptance list or release prose.
9. **Commit dates and release dates differ.** v0.1.0 source commit/tag points to June work while CHANGELOG dates v0.1.0 as 14 July. Use release metadata to establish publication date; use Git commit timestamps only for development history. v0.3.0 tag precedes the HEAD documentation follow-up.
10. **Do not turn designs into API promises.** Supply-chain enforcement, advanced CNI, external plugins, payments/invoicing and the full stateful lifecycle must be labeled explicitly as proposals/future exercises.
